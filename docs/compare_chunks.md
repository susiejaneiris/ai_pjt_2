## 관찰

- **청크 크기는 1000 / 200 이 가장 좋았다 (small 기준 85.7%).**
  - 500 / 100 은 청크가 1,029개로 늘고 조문이 잘게 쪼개져, 같은 조문의 다른 항이 따로 경쟁하다 "음주 킥보드"(Q20)를 놓쳤다.
  - 1500 / 300 은 청크 하나에 여러 항 · 문단이 섞여 의미가 흐려져 "킥보드 헬멧"(Q21)을 놓쳤다.
  - 기획 단계의 실측(조문의 85%가 1,000자 이하 → 근거 1개 = 조문 1개)과 결과가 일치한다.
- **근거 길이는 청크 크기에 비례해 늘지 않는다.** 조문 전체 확장(`expand_articles`) 때문에 어떤 크기든 조문은 통째로 들어가고, 차이는 위키 · 판례 청크에서만 난다 (4,484 → 5,687자).
- **임베딩 모델을 large 로 바꾸자 90.5% 로 올랐다.** small 로는 합치는 방식 6가지를 다 바꿔도 못 잡던 Q02(“이사를 가야 해요” ↔ 임차권등기명령), Q04(“자동으로 연장” ↔ 묵시적 갱신 해지)를 잡았다 — 일상어와 조문 사이 의미 거리는 검색 방식보다 **임베딩 모델의 차이**였다.
- 결정: `chunk_size 1000` · `chunk_overlap 200` 유지, `embedding_model` 을 `text-embedding-3-large` 로 변경 (`python -m scripts.reindex` 로 외부 문서를 다시 받지 않고 재색인).
- 답변까지 포함한 전체 평가(v8): 검색 적중률 90.5% · 인용 적중률 90.5% · 잘못된 거절 0% · 거절 정확도 100% (`docs/eval/v8_large_embedding.md`).
