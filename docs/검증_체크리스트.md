## 1. 필수 기능 (F2001 ~ F2012)

| 번호 | 확인 항목 (명세) | 상태 | 확인 결과 · 근거 |
|---|---|---|---|
| F2001 | 항목 메타데이터 로드, 약 100건 이상 | ✅ | `data/items.json` 276건 (20개 분야) |
| | 항목 1건 = 검색용 텍스트 1개, 의도한 속성 포함 | ✅ | 법률명 · 약칭 · 분야 · 소관부처 · 시행일 · 목적 · 주요 조문 제목 (`prep/item_text.py`) |
| F2002 | 임베딩해 Vector DB 컬렉션에 색인, 청크 수 확인 | ✅ | `law_meta` 276청크 = 항목 수 (`python -m scripts.build_index`) |
| | 다시 색인해도 중복 저장 안 됨 | ✅ | 두 번째 실행: 276 → 276 (id = item_id 덮어쓰기) |
| | 화면에 색인 건수 표시 | ✅ | 머리글 "법률 276건 색인" |
| F2003 | 도메인 전문가 역할 프롬프트 1, 파싱 가능한 형식 | ✅ | "너는 한국 생활법령 전문가다", JSON `{in_scope, queries, articles}` |
| | 항목 자체 문서는 항상 검색 대상 | ✅ | 법률 조문 전체 + 같은 제목 위키를 항목 자체 문서로 항상 색인 (`base_documents`) |
| F2004 | 외부 출처에서 후보 수집 → 프롬프트 2 로 선별 | ✅ | 조문 · 판례 · 법령해석례(PDF) · 생활법령 Q&A · 위키 후보 → "사서" 프롬프트가 번호로 선별 |
| | 항목 자체 문서는 어떤 제외 규칙보다 우선 | ✅ | 선별과 무관하게 base 문서 먼저 색인 |
| | 본문 + 원문 출처(URL 또는 파일명 · 쪽) | ✅ | 조문 · 판례 · 위키 URL, PDF 는 "법제처, 「…」(하), 1149~1152쪽" |
| | 이미 수집한 검색어는 다시 수집 안 함 | ✅ | `data/collected.json` — 같은 질문 재질문 시 "전에 받은 질문이라 모아 둔 문서를 다시 써요" |
| | 호출 제한 환경 대비 문서 묶음 | ✅ | `data/fallback/` 7개 법률 |
| F2005 | 청크 크기 · 중복 길이 적용, 별도 컬렉션 | ✅ | `law_docs` 5,738청크, `chunk_size 1000 / chunk_overlap 200` (설정 파일) |
| | 청크에 제목 · 원문 출처 · 관련 항목 저장 | ✅ | 메타 키: title · url · citation · item_id · item_name · doc_id · source_type · date |
| | 청크 id 가 항목끼리 덮어쓰지 않음 | ✅ | `law_001:article-276291-제1조:0` (항목 ID:문서 ID:순번) |
| | 크기를 바꾸면 청크 수가 달라짐 | ✅ | `docs/compare_chunks.md` (500/100 · 1000/200 · 1500/300 비교) |
| F2006 | 선택 항목의 메타 청크는 항상 근거에 포함 | ✅ | id 로 꺼내 항상 [근거 1] (`retrieve_sources`) |
| | 의미 유사도로 외부 청크 검색, 병합 · 중복 제거 | ✅ | item_id 필터 검색 → RRF 병합 → 같은 청크 · 같은 본문 · 같은 문서 3단계 중복 제거 |
| | Top-k 설정으로 조정, 바꾸면 근거가 달라짐 | ✅ | `top_k` 8 (평가 v7: 6 → 8 에서 적중률 81.0 → 85.7%) |
| F2007 | LangGraph retrieve · generate 두 노드 | ✅ | 그래프 노드: `__start__ → retrieve → generate → __end__` (`python -m rag.graph`) |
| | 검색된 문서만 사용, 출처 유형 구분 | ✅ | 프롬프트 3 규칙 + 근거마다 유형 표시(항목 메타데이터 · 조문 · 판례 · 법령해석례(PDF) · 생활법령 Q&A · 위키백과) |
| | 근거가 없으면 "확인되지 않습니다" | ✅ | 함정 질문 거절 정확도 100% (평가 v11 · 넓힌 분야 세트) |
| F2008 | 주요 주장에 근거 번호, 인용된 근거만 표시 | ✅ | `[근거 N]` → 금색 배지, `cited_sources` 로 인용된 것만 |
| | 제목 · 원문 출처 함께 | ✅ | 근거 카드: 유형 · 제목 · 원문 링크(또는 책 · 쪽) · 발췌 |
| | 인용 0건이면 화면 안내 | ✅ | "ⓘ 답변에 인용된 근거가 없어요…" |
| F2009 | 목록에서 항목 선택, 항목별 대화 기록 분리 | ✅ | 사이드바 분야 → 법률, `histories[item_id]` |
| F2010 | 도메인 특화 기능 1개 이상, 근거 함께 제시 | ✅ | ① 사실일까?(팩트체크 판정 도장) ② 조문 쉽게 읽기 ③ 쟁점 나누기(복합 질문) — 모두 색인 문서만 근거 |
| F2011 | 자연어 조건 → 맞는 항목만 → 선택하면 대화로 | ✅ | 법률 용어로 바꿔 검색 → LLM 이 조건에 맞는 법률만 카드로 → 누르면 그 대화 + 적은 상황을 바로 질문 |
| F2012 | 수집 · 생성 중 진행 상태 | ✅ | `st.status` — 검색어 · 색인한 문서 · 버린 후보 표시 |
| | 키 누락 · 색인 없음 안내 | ✅ | GMS_KEY 를 비우고 실행 → "GMS_KEY가 설정되지 않았어요" (오류 추적은 로그에만). 색인 0건 안내 문구 있음 — 단, 앱이 시작할 때 비어 있으면 자동 색인하므로 평소엔 보이지 않음 |
| | 위험 도메인 면책 안내 | ✅ | 모든 법률 법률 안내 + 금융 34건 · 건강 19건 추가 안내 (`prep/disclaimer.py`) |

## 2. 심화 기능 (F2013 ~ F2016) — 4개 모두 선택

| 번호 | 확인 항목 | 상태 | 확인 결과 · 근거 |
|---|---|---|---|
| F2013 | HTML · CSS · JS 화면, 화면 · 서버 분리, 요청 · 응답 형식 | ✅ | `web/` + FastAPI `server.py` — API 8개(`/api/chat` 등 NDJSON 스트림), 형식은 `server.py` 머리말 |
| | 질문 입력 · 답변 · 근거 표시 | ✅ | `/api/status` · `/api/items` 응답 확인, 채팅 폼 · 근거 카드 구현 |
| | (참고) Streamlit 에만 있는 기능 | ⚠️ | 쟁점 나누기 모드는 Streamlit 화면에만 있음 (필수 아님) |
| F2014 | 넉넉히 가져와 다양성 선별, 유사도 vs MMR 차이 | ✅ | `search_type: mmr`(fetch_k 30, λ 0.5), `docs/compare_search.md` · `scripts/compare_search.py` |
| F2015 | 대표 질문 5개 이상, RAG 전후 답변 나란히, 3기준 비교 문서 | ✅ | `docs/RAG_전후_비교.md` 7문항(함정 1) — 사실 정확성 · 근거 제시 · 모른다고 답하는지 |
| | (참고) 최신 설정으로 다시 실행 | ⚠️ | 10-21 실행본 — 이후 조문 지목(v11) 등으로 RAG 쪽이 더 좋아짐. 제출 전 `python -m scripts.compare_rag` 재실행 권장 |
| F2016 | 종류가 다른 출처를 함께 색인, 근거에 종류 구분 | ✅ | 법령 API(JSON) · 법령해석 사례집(PDF) · 어린이 생활법령(PDF) · 위키백과 — 근거에 📜 ⚖️ 📘 💬 📖 |
| | 출처별 수집 · 청킹을 달리한 이유 | ✅ | 설계문서 3-4 (판례는 판시사항 · 판결요지 따로, 해석례는 질의·회답 / 이유 따로 등) |
